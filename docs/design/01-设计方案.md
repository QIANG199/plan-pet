## 修订说明（v1.8 → v1.9）

OpenCode 接入运行时存在感，契约加一个点（向后兼容：旧固件忽略它）：

- **第 2 页更名 `OPEN CODE`**：屏显从 `OPENCODE GO` 改为 `OPEN CODE`（套餐本体与快照键 `opencodeGo`、env 键 `OPENCODE_GO_KEY` 不变）。
- **运行时呼吸灯**：opencode 侧没有 hooks 适配器，改由中转服务自己判（`server/src/opencode-runtime.js`，每 5 秒查会话库 `~/.local/share/opencode/opencode.db` 及 `-wal` 最近 5 分钟内有无写入；扫描失败沿用上一次结果）。桌面版是 Electron 常驻应用，进程/窗口在 ≠ 在用，日志更是持续心跳，只有会话库在会话活动时才落笔（桌面版与 TUI 共用同一库）。最近有会话活动 → 快照 `pet.dots.opencode=true`，第 2 页绿点亮（与 GLM / CURSOR 同款呼吸动画）。
- **桌宠兜底动画**：opencode 最近有会话活动且桌宠处于 idle 时，快照呈现为 `agent=opencode`、`state=typing`（`pet.js` 的 `withRuntime`）。hooks 的 busy / happy / error 不被打断，15 分钟睡眠计时也不由它重置——挂着不干活不算活动，息屏节奏不变。

## 修订说明（v1.7 → v1.8）

第三份额度 + 卡内翻页，中转服务契约新增一个键（向后兼容：旧固件忽略它）：

- **OpenCode Go 额度**：新增 `server/src/opencode.js`，拉 `opencode.ai/zen/go/v1/usage`（`Authorization: Bearer`，key 来自 `.env` 的 `OPENCODE_GO_KEY`），快照键 `opencodeGo`，含 `5h`（rolling）/ `week` / `month` 三个美元窗口。查法与 cc-switch 的 `opencode_go` 探测一致。
- **额度卡改两页**：第 1 页保持老布局（GLM + CURSOR 两块同页，各占半张卡），第 2 页单独放 OPENCODE GO——它有 3 个窗口行，半张卡装不下。上下滑动翻页，卡右下角两个页点指示当前页。翻页是纯显示端行为，服务端不参与。
- **Claude Code 适配器**：新增 `hooks/claude-hook.js`（Claude Code 的事件名与契约同名，适配器只贴 `source: claude` 后转发），`hooks/install.js` 往 `~/.claude/settings.json` 追加 6 个钩子——不与用户已有的 ccstatusline / codegraph 钩子争位。状态机从两条 lane 扩到三条，动画优先级 zcode → claude → cursor；Claude Code 没有自己的额度卡，所以只有 `dots.claude` 供状态机用、屏上不点绿点。**固件不动**：桌宠本来就按快照的 `pet.state` 播帧。
- **OTA 指令推**：新增 `POST /api/ota/push`，服务端把它写进快照的 `ota.forceAt`，面板下一次轮询（约 1 秒）即开始下载，不必等 6 小时自检；取走 bin 即清零，一次置位只对应一次下载。串口 `OTA` 与 6 小时自检保留。
- 三份额度互不依赖：任一份失败只让该页 `fail`；首拉也不再串行（一个来源慢不拖另外两个）。

## 1. 项目概述

用微雪 ESP32-S3-Touch-LCD-3.49（A 款带锂电池，SKU=32373）开发一块桌面摆件面板，同时展示：

1. **GLM Coding Plan（国际版 Z.ai）额度**：`5h` 与 `7d` 窗口的已用百分比、行内倒计时
2. **Cursor Pro 额度**：`composer & grok` / `other` 已用百分比、账期结束倒计时
3. **OpenCode Go 额度**：`5h` / `week` / `month` 三个美元额度窗口的已用百分比、行内倒计时
4. **clawd 桌宠**：随会话事件切换；绿点表示该应用在跑（可同时亮），桌宠动画跟 **当前代理**

GLM 与 Cursor 仍同页；OpenCode Go 单独一页（3 个窗口行，半张卡放不下），两页之间上下滑动切换。开发者为 Java 后端背景、首次接触硬件开发，方案向「逻辑简单、易调试、文档完备」倾斜。额度面板是哑终端：不持有 Cursor 登录态、Z.ai Key 与 OpenCode Go Key，不实现业务规则。

## 3. 系统架构

```
┌──────────────── 你的电脑（Node.js 中转服务 :3737）──────────────────────┐
│  鉴权：X-Panel-Token；首次运行写 Windows 防火墙入站规则                      │
│                                                                          │
│  Cursor 适配器 ──┐                  ┌── Cursor 账单接口                    │
│  ZCode 适配器  ──┼─→ 事件接收/状态机 ─┤   (state.vscdb 读 token)              │
│                  │                  ├── Z.ai monitor API (API Key)         │
│                  │                  └── OpenCode Go usage (Bearer key)     │
│                  ↓                                                       │
│           聚合内存状态 ──→ GET /api/dashboard                               │
└─────────────────────────────────┬────────────────────────────────────────┘
                                  │ HTTP 轮询（WiFi，每 1s，直连配置的 PC IP）
                                  ↓
                         ┌─────────────────┐
                         │  ESP32-S3 面板   │
                         │  LVGL 渲染       │
                         │  额度卡+桌宠动画  │
                         └─────────────────┘
```

**数据流**：

- 事件流：Cursor / ZCode / Claude Code 触发 hooks → **本仓库适配器**（不是 clawd 的 `cursor-hook.js`）POST `/api/event` → 状态机更新桌宠
- 额度流：中转服务每 5 分钟拉 Cursor / Z.ai / OpenCode Go → 内存缓存（三份互不依赖，一个失败不影响另外两个）
- 显示流：额度面板每 1 秒 GET `/api/dashboard`，一次拿全；`nextResetAt` 由设备本地倒计时
- 发现流：额度面板直连显式配置的 PC IP（串口 / 触屏设置页写 NVS）；mDNS 已移除

## 4. 外部接口依赖

### 4.1 GLM Coding Plan（国际版）

- 端点：`GET https://api.z.ai/api/monitor/usage/quota/limit`
- 认证：`Authorization: <API_KEY>`（**无** `Bearer` 前缀，与 cc-switch #1588 一致）
- **字段映射（v1.0 写反，此处以 #1588 抽取逻辑为准）**：

| `limits[].type` | 判定 | 面板 |
|---|---|---|
| `TOKENS_LIMIT` 且 `unit=3, number=5` | 5 小时窗口 | 上条 % + 行内倒计时 |
| `TOKENS_LIMIT` 且 `unit=6, number=7` | 7 天窗口 | 下条 `7d` % + 行内倒计时；无此条则隐藏 |
| 其它 `TOKENS_LIMIT` | 按 `nextResetTime` 升序兜底 | 短窗 / 长窗 |
| `TIME_LIMIT` | MCP 月度次数 | **不做** |

只使用 `percentage` 与 `nextResetTime`。`data.level` 入库。不使用 `usage/currentValue/remaining`。

### 4.2 Cursor（非官方接口，社区验证方案）

- 认证：WorkOS 会话。本机验证有效写法是 Cookie `WorkosCursorSessionToken={cachedAuthId}::{accessToken}`（`adminSettings.cachedAuthId` + `cursorAuth/accessToken`）。只丢 accessToken 会 401
- **取用字段（已拍板）**：`membershipType`、`billingCycleStart`、`billingCycleEnd`、`plan.autoPercentUsed`、`plan.apiPercentUsed`
- 进度条只用两个 Percent。禁止用 `plan.used/limit` 当百分比
- CURSOR 标题右侧倒计时 = `billingCycleEnd`（本机 2026-09-21）
- 不取 on-demand、不取 aggregated events

### 4.3 ZCode hooks（官方机制）

- 配置：`~/.zcode/cli/config.json`，`hooks.enabled: true`；只用用户级，不用项目级
- 协议：stdin 一行 JSON（`hook_event_name`、`session_id`、`tool_name`），stdout 必须在约 800ms 内写出合法 JSON，POST 异步
- 监听：`UserPromptSubmit` / `PreToolUse` / `PostToolUse` / `PostToolUseFailure` / `Stop`
- 安装：本仓库脚本往用户级 hooks **追加**命令，不覆盖已有 clawd 条目

### 4.4 Cursor hooks（自写适配器，禁止原样复用 clawd）

clawd-on-desk 的 `hooks/cursor-hook.js` **不能**直接用：

- 它 POST 到 clawd 的 `23333–23337/state`，不是本服务 `:3737/api/event`
- 事件名是 camelCase，与契约不一致
- 它把 `postToolUseFailure` 映射成 working，本方案要 error
- 与 clawd 同时安装会争用 `~/.cursor/hooks.json`（应并存为多条命令）

本仓库适配器负责：

1. 800ms 内对 Cursor 写出合法 stdout JSON（`beforeSubmitPrompt` 回 `{ continue: true }`，其余 `{}`）
2. 把事件名归一成第 5.2 节契约后再 POST
3. 探测失败时静默丢事件，不得阻塞 IDE

| Cursor 钩子名 | 契约 `event` |
|---|---|
| `beforeSubmitPrompt` | `UserPromptSubmit` |
| `preToolUse` | `PreToolUse` |
| `postToolUse` | `PostToolUse` |
| `postToolUseFailure` | `PostToolUseFailure` |
| `stop` | `Stop`（payload.status 为 error 时仍报 `Stop`，由状态机看是否进 error） |
| `sessionStart` | `SessionStart`（仅用于把 sleeping 唤醒为 idle） |
| 其余 | 忽略 |

### 4.5 Claude Code hooks（官方机制，事件名即契约名）

- 配置：`~/.claude/settings.json` 的 `hooks`（用户级；项目级不用），`hooks/<事件名>: [{ hooks: [{ type: "command", command: "…claude-hook.js", timeout: 10 }] }]`
- 事件名与第 5.2 节契约**同名同义**，适配器只贴一个 `source: "claude"` 就转发，不做别名映射：

| Claude Code 事件 | 契约 `event` |
|---|---|
| `SessionStart` | `SessionStart`（仅唤醒，不改状态） |
| `UserPromptSubmit` | `UserPromptSubmit` |
| `PreToolUse` | `PreToolUse` |
| `PostToolUse` | `PostToolUse` |
| `PostToolUseFailure` | `PostToolUseFailure`（payload 带 `error` / `is_interrupt`，屏上进 error） |
| `Stop` | `Stop`（payload 没有 status 字段，一律进 happy） |
| 其余（`Notification`、`SubagentStart/Stop`、`PreCompact`…） | 不注册、忽略 |

- 省略 `matcher` 即对所有工具生效（官方文档：omit 或 `"*"` = 每次事件都触发），比写 `"*"` 少一层出错可能
- stdout 保持静默：Claude Code 会把 hook 的 stdout 当决策对象解析，本适配器不发表意见，只 POST 事件
- 安装：`hooks/install.js` 往 `~/.claude/settings.json` 的 `hooks` **追加**条目，不动用户已有的 ccstatusline / codegraph 等钩子（重跑幂等）

### 4.6 OpenCode Go（一手 usage 路由，未文档化）

- 端点：`GET https://opencode.ai/zen/go/v1/usage`
- 认证：`Authorization: Bearer <OPENCODE_GO_KEY>`。**用量端点只认 Bearer**，与推理侧 `/messages` 的 `x-api-key` 不能互换；401 与 403 语义分开：403 = key 有效但该 workspace 没有 Go 订阅，401 = key 无效
- 响应：`{"usage":{"rolling"|"weekly"|"monthly":{"status":"ok"|"rate-limited","percent":0-100,"resetsAt":ISO8601}}}`

| 上游窗口 | 文档口径 | 面板 |
|---|---|---|
| `rolling` | $12 / 5 小时 | 第 1 行 `5h` |
| `weekly` | $30 / 周 | 第 2 行 `week` |
| `monthly` | $60 / 月 | 第 3 行 `month` |

只使用 `percent` 与 `resetsAt`，端点不回传金额（只给百分比）。三条解析约定：

- `percent` 为 0 时上游的 `resetsAt` 是「now + 窗口时长」的占位值，丢弃、不显示倒计时
- `percent` 兼容数字与字符串数字；坏窗口跳过、好窗口保留，不整份失败
- 三个窗口一个都解析不出来 = 响应形态不认识 → 该页 `fail`（端点未文档化，上线当天就改过一次形态，见 cc-switch `coding_plan.rs` 的 `opencode_go` 探测）

```json
  "opencodeGo": {
    "ok": true,
    "h5":    { "pct": 20, "nextResetAt": 1760769000 },
    "week":  { "pct": 8,  "nextResetAt": 1761280000 },
    "month": { "pct": 4,  "nextResetAt": 1763600000 }
  },
  "pet": {
    "agent": "zcode",
    "state": "typing",
    "since": 1760759160,
    "dots": { "zcode": true, "cursor": true, "opencode": false }
  },
  "ota": { "forceAt": null }
}
```

约定：

- `ok=false` 时该页显示 `fail`，另两页与桌宠继续
- Cursor 快照键 `auto` / `api` 对应屏上 `composer & grok` / `other`（来自 `autoPercentUsed` / `apiPercentUsed`）
- 老套餐无 7d 额度：`glm.week` 为 `null`，下条进度条不画
- `opencodeGo` 键对应屏上 `5h` / `week` / `month`（上游 `rolling` / `weekly` / `monthly`）。窗口或 `nextResetAt` 为 `null` 时该行只显 `--`（已用 0% 的占位重置时刻在服务端就被丢掉）。`.env` 未配 `OPENCODE_GO_KEY` 时整页恒 `ok=false`
- `glm.peak`：北京时间每天 14–18 点 GLM 用量按 3 倍计的高峰标志；服务端在响应时点算（不受 5 分钟刷新间隔影响），面板在 GLM 标题后渲染「• 3x」（3x 用警示橙）。`glm.ok=false` 时以 false 处理
- `pet.agent ∈ {cursor, zcode, claude, opencode, null}`：桌宠动画跟谁走（同时 busy 时为 zcode；`opencode` 仅在运行时在场兜底 idle 时出现，见 §6）
- `pet.state ∈ {idle, thinking, typing, happy, error, sleeping}`：桌宠动画
- `pet.dots.zcode` / `pet.dots.cursor`：对应额度卡绿点，可同时为 true
- `pet.dots.opencode`：OpenCode 页（屏显 `OPEN CODE`）呼吸灯 = OpenCode 会话库最近 5 分钟内有写入（服务端 5 秒一轮）且桌宠未 sleeping；它是最近活动不是事件，与额度拉取成功与否无关
- `ota.forceAt`：服务端置位的「立刻升级」时刻（Unix 秒，未置位为 `null`）。面板看到新值即跳过 6 小时自检直接开始下载；取走 bin 后服务端清零，故一值只触发一次。详见 5.4
- 倒计时用 `nextResetAt` / `cycleEnd`（Unix 秒），设备本地递减
- 无 `resetMin`、无 `onDemand`、无 `includedUsd`

### 5.2 `POST /api/event`（适配器上报）

```json
{
  "source": "zcode",
  "event": "PostToolUse",
  "tool": "Write",
  "session": "session-123",
  "ts": 1760759160
}
```

- `source ∈ {cursor, zcode, claude}`（三条 lane 并存互不影响）
- `event` 只接受上表契约名。Cursor 别名在适配器内消化，服务端不认 camelCase
- 无令牌 → 401；未知 event → 204 忽略；未知 source 被状态机拒绝

### 5.3 发现、配网、防火墙

- 面板直连显式配置的电脑 IP（无 mDNS；服务端也不做广播）
- 首次运行尝试添加 Windows 防火墙 TCP 3737 入站规则（失败则日志提示手动放行）
- 额度面板保存：WiFi SSID/密码、电脑 IP、面板令牌（串口 / 触屏设置页 / Web 配网页写 NVS）。DHCP 换 IP 后需重设
- 首次配网：USB 烧录后串口写入（设备 USB 常亮，不另做 SoftAP）。改 WiFi 同样走串口
- 令牌：中转服务首次启动生成并打印；用同一串口命令写入 NVS

### 5.4 `GET /api/ota/info` + `GET /api/ota/bin` + `POST /api/ota/push`（面板 OTA 升级）

面板固件检查更新（醒着、服务可达、USB 供电或电量 ≥30%，每 6 小时；开机 2 分钟后首查），比较 build 号后经 `/api/ota/bin` 下载 app 镜像写入空闲 OTA 槽，MD5 校验通过自动重启。三个端点均在 `X-Panel-Token` 鉴权之后。

**指令推（`POST /api/ota/push`）**：面板是纯 HTTP 客户端（不监听、也没被服务器记地址），服务器推不进去，所以"推"借它每秒拉的那条快照通道：置位后 `/api/dashboard` 的 `ota.forceAt` 变成当前时刻，面板下一次轮询（醒着时约 1 秒）就开始下载，不必等 6 小时自检、也不用跑去按设备。约定：

- **一次置位只对应一次下载**：`/api/ota/bin` 被取走即清零；面板侧按「值变化」触发（同一值不重复），重启后也不会重复
- 不是"每次构建自动推"：bin 落盘不置位，只有显式调用这个端点才置位（半成品构建不会自己装上设备）
- 置位时的守卫与自检共用：醒着、`POWER_NORMAL`、服务可达；非自检（forced）路径跳过电量护栏。息屏期间保持 pending，等唤醒后联网窗口到了再走
- bin 不存在时返回 404 且不置位；6 小时自检保留为兜底

`/api/ota/info` 响应：

```json
{ "ok": true, "build": 1756270293, "size": 5738516 }
```

约定：

- `build` = 固件 bin 的 mtime（Unix 秒）；固件端用自身编译时刻（`__DATE__`/`__TIME__`）比较，`build` 超出本地 15 分钟以上才升级（bin 落盘时间天然晚于编译时刻数分钟，容差内的视为同一构建，防止自升级循环），重编译即出新版本
- `size` = app 镜像字节数，面板用作 `Update.begin()` 预分配与进度基准
- bin 路径默认 `firmware/.pio/build/desktop-pet/firmware.bin`（app 镜像，非 factory 合并包），`.env` 的 `OTA_BIN` 可覆盖；文件缺失时 `ok=false`（HTTP 404），面板按「无更新」处理并退避
- 下载中断或校验失败：旧固件不受影响，1 小时后重试；写槽期间断电同样仍跑旧固件

## 6. 桌宠状态机

状态机只在中转服务。额度面板只播 `pet.state` 对应帧。

| 契约事件 | 下一态 | 素材 |
|---|---|---|
| （启动 / 尚无事件） | idle | clawd-idle.gif |
| SessionStart（当前为 sleeping） | idle | clawd-idle.gif |
| UserPromptSubmit / PreToolUse | thinking | clawd-thinking.gif |
| PostToolUse | typing | clawd-typing.gif |
| Stop（非失败） | happy（保持 4s） | clawd-happy.gif |
| PostToolUseFailure，或 Stop 且失败 | error（保持 4s） | clawd-error.gif |
| happy / error 满 4s | idle | clawd-idle.gif |
| 15 分钟无任何事件 | sleeping | clawd-sleeping.gif |

规则：

- **Idle** 是清醒待机：一轮已结束或尚未调工具，但还不到入睡。不是 typing，也不是 sleeping
- typing **仅**在工具调用进行中（PreToolUse 之后、Stop 之前的 PostToolUse 段）
- Cursor 若漏发 Stop，最后一次 PostToolUse 后约 10s 无新工具则视为结束（happy → idle）
- happy / error 可被新的 UserPromptSubmit / PreToolUse **立即打断**；Stop 之后迟到的 PostToolUse 不打断 happy / idle
- 三条 lane（zcode / claude / cursor）各自独立：谁在 thinking/typing/happy/error 谁的绿点亮（Claude Code 没有额度卡，故只有 `dots.claude` 供状态机用、屏上不点）。桌宠动画同时 busy 时按 zcode → claude → cursor 定胜负，避免被后到的 Cursor 事件拽走
- opencode 不占 lane：它的「运行时在场」（会话库活动检查，5 秒一轮）只在快照出口叠加——桌宠 idle 时兜底成 `agent=opencode` + typing，`dots.opencode` 随会话活动亮/熄（sleeping 时熄）。hooks 的 busy / happy / error 优先于兜底，睡眠计时也不由它重置：进程挂着 ≠ 活动，息屏节奏与纯 hooks 时代一致
- 15 分钟计时器在每一次成功处理的 `/api/event` 上重置

## 7. UI 规格（详见设计稿）

- 物理分辨率：172 × 640（IPS，QSPI，AXS15231B，电容触摸）
- 横屏画布：640 × 172；驱动使用微雪例程的旋转宏（`USER_DISP_ROT_90`），触摸坐标同步旋转
- 布局：内边距 6px；状态列 **80×160** ｜ 间距 8 ｜ 额度列 **372** ｜ 间距 8 ｜ 桌宠 **160×160 正方形**。验算 6+80+8+372+8+160+6=640，高 6+160+6=172
- 状态列：时间（顶，**横向居中**）→ 其下短分隔线（52px，不拉满）→ 中部留空 → 底行 WiFi + 电源图标 + 百分比。充电用闪电电池，供电用填充电池。LVGL 用 `LV_SYMBOL_CHARGE` / `LV_SYMBOL_BATTERY_*`
- 额度卡 372×160 分两页：第 1 页 `GLM` + `CURSOR`（老布局原样，各占半张卡），第 2 页 `OPEN CODE`
- 翻页：卡上**上下滑动**（竖向位移 ≥26px 才算，轻点不翻），到头停住不循环；卡右下角两个 5px 页点指示当前页（当前页 muted ink，其余 track）。页码只存内存，重启回第 1 页；翻页只在显示端，服务端不参与
- GLM 半卡：`GLM` + 绿点（高峰时段标题后加 `• 3x`）；行左 `5h` / `7d`；行右倒计时 + 百分比
- CURSOR 半卡：`CURSOR` + 绿点，标题右侧账期倒计时；行左 `composer & grok` / `other`；行右百分比。数据键仍为快照 `auto` / `api`
- OPEN CODE 页：标题 `OPEN CODE` + 绿点（运行时在场：最近有会话活动就亮，同款呼吸动画）；行左 `5h` / `week` / `month`；行右倒计时 + 百分比
- 绿点：GLM / CURSOR 侧跟 hooks 状态（thinking/typing/happy/error 常亮，两边可同时亮），OPEN CODE 侧跟运行时在场；桌宠动画另按 zcode → claude → cursor 优先选态，idle 且 opencode 最近有会话活动时兜底 typing
- 进度条高 7px。已用 `[0,70)` 绿 `#22c55e`；`[70,90)` clawd 橙 `#f0805a`；`[90,∞)` 红 `#ef4444`
- 桌宠区 160×160；帧按正方形画布居中（约 150×120 可视），8–12fps
- 主题：深色默认 / 浅色；点桌宠切换。BOOT 仅调试
- **真机字号门禁**：时间 ≥16px，卡标题 ≥12px，进度标签与倒计时 ≥11px
- 屏上无汉字；失败态 `fail`
- 设计稿：`docs/design/screen-layout.html` v11

## 8. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 构建 / 烧录 | PlatformIO（Arduino 框架） | 与 Cursor 同编辑器；补全、依赖、烧录一体。**不安装 Arduino IDE** |
| 厂商驱动 | 微雪 Demo 包 `Arduino/libraries` 拷进工程 | 官方未提供 PlatformIO 板型；板子按 ESP32-S3 + 16MB Flash + 8MB OPI PSRAM 配置 |
| 对照手段 | 官方 Arduino IDE 例程（可选） | 仅当 PlatformIO 点不亮时，用来区分「硬件坏了」还是 `platformio.ini` 错了 |
| UI | 微雪移植的 LVGL（跟例程版本，不混 8/9） | 卡片、进度条、字库 |
| 帧存储 | LittleFS | 深/浅两套 RGB565；6 态。帧数以 GIF 实测为准，不假定 12 |
| 动画 | 构建期 GIF 按主题背景合成后转 RGB565 | 吉祥物 GIF 带透明通道，RGB565 无 alpha；运行时不解码 GIF |
| 中转服务 | Node.js，少依赖 | 开机自启（Windows 任务计划或启动文件夹，阶段 6） |
| 时间 | NTP + PCF85063，时区 Asia/Shanghai | 断网后 RTC 仍走；倒计时用绝对时间戳 |

动画体积（上限估算）：单帧 160×160×2 ≈ 51KB；6 态 × 2 主题 × 12 帧 ≈ 7.4MB。超了先降帧数，不砍浅色主题。实际 GIF 按正方形画布居中裁切，不是拉满 160。

## 9. 关键设计决策（ADR 摘要）

1. **PC 中转而非 ESP32 直连**：Cursor token 在本机 SQLite；中转同时做事件聚合与额度缓存。代价：面板依赖电脑开机。
2. **轮询而非 WebSocket**：1s 轮询代码少、断线自愈；局域网流量可忽略（2026-08 由 2s 提频，mDNS 移除后单次轮询只剩 TCP+HTTP）。
3. **状态机在服务端**：固件保持哑终端。
4. **构建期按主题烤帧，而非运行时解 GIF / 合成 alpha**：换 Flash 换简单固件。透明通道不能烤死在单一背景上。
5. **Arduino 框架 + PlatformIO，而非 ESP-IDF，也而非 Arduino IDE**：跟微雪 Arduino 例程 API；日常开发留在 Cursor。
6. **显式配置 PC IP 而非 mDNS**（2026-08 反转，原决策为「mDNS 主机名而非写死 IP」）：目标局域网组播不通，mDNS 解析从未成功，且逐次解析给轮询附加大额组播与阻塞开销；现固件只认字面 IP / 普通 DNS，服务端不再广播。代价：DHCP 换 IP 需串口/设置页重设 HOST（运行期 NVS 配置，仍非编译期写死）。
7. **自写 hooks 适配器，而非安装 clawd 的 cursor-hook.js**：端口、路径、事件名、失败态映射都不同；与 clawd 并存。

## 10. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| Cursor 非官方接口变动 | 高 | 跟 2+ 开源实现；该卡 `fail`，不影响其余 |
| OpenCode Go 用量路由变动 | 中 | 未文档化的一手路由，形态会变；逐窗口防御解析 + 完全不认识才整页 `fail`，不影响另外两页 |
| WorkOS token 过期 | 中 | 每次拉取重读 vscdb；失败提示重新登录 Cursor |
| 真机字号偏小 | 中 | 阶段 2 字号门禁；不达标减文案（周条、on-demand、倒计时择一） |
| PlatformIO 无官方板型 | 中 | 先拷微雪库 + 对齐 Flash/PSRAM/USB CDC；仍失败再用官方 Arduino 例程对照 |
| 电脑 IP 被 DHCP 更换 | 低 | 串口 / 触屏设置页重设 HOST；路由器可给电脑绑定静态租约 |
| WiFi 断连 | 低 | 图标置灰、指数退避；显示最后快照；倒计时本地继续 |
| 帧体积超 Flash | 中 | 6 态×双主题；构建脚本打印实测字节；超限降帧 |
| 钩子拖慢 IDE | 中 | 适配器 800ms 内先写 stdout，再异步 POST |
| 局域网伪造事件 | 低 | 面板令牌；家用仍建议开启 |
